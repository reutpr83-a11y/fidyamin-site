# reel-edit — עריכת ריאיון לרילס עם כתוביות סימטריות

צינור עבודה שחותך קטעים מריאיון, מדביק אותם לרילס, וצורב כתוביות עברית
מיושרות למרכז עם שבירת שורות סימטרית.

## למה זה קיים

הסשן שבו נבנה הכלי לא הצליח להוריד את סרטון המקור: מדיניות היציאה לרשת של
הסביבה חסמה את `t.me` (‏403 על CONNECT), וגם `huggingface.co` חסום, כך שאי
אפשר היה להוריד מודל תמלול. הכלי מריץ את אותה עבודה על מכונה עם גישה לרשת.

## התקנה

```bash
pip install yt-dlp faster-whisper pillow imageio-ffmpeg
# ffmpeg מערכתי עדיף; imageio-ffmpeg הוא גיבוי אם אין
```

מומלץ להתקין גופן עברי מודרני (למשל Noto Sans Hebrew / Rubik / Heebo) —
אחרת fontconfig יבחר את מה שיש, בדרך כלל DejaVu Sans.

## הרצה

```bash
# 1. הורדת המקור
python3 edit_reel.py fetch --url https://t.me/i24NewsIL/43876 --work work/

# 2. תמלול עברית עם חותמות זמן ברמת מילה
python3 edit_reel.py transcribe --work work/

# 3. בחירת הקטעים: קוראים את work/transcript.txt וכותבים work/cuts.json
cp cuts.example.json work/cuts.json   # ואז עורכים

# 4. חיתוך, כתוביות ורנדור
python3 edit_reel.py build --work work/ --aspect 9:16
```

הפלט: `work/reel_9x16.mp4`, וגם `subtitles.ass` ו-`subtitles.srt` להעלאה
נפרדת בפלטפורמות שתומכות בקובץ כתוביות.

## מבנה cuts.json

```json
{"cuts": [
  {"start": 12.40, "end": 18.90, "role": "q"},
  {"start": 19.10, "end": 31.75, "role": "a"}
]}
```

`role` הוא `q` לשאלת המראיינת ו-`a` לתשובת המרואיינת; לכל אחד סגנון כתובית
נפרד. אם משמיטים את `text`, המילים נשלפות מ-`transcript.json` לפי חותמות
הזמן. הסקריפט לא מנסח מחדש ולא מסדר מחדש — הוא חותך בזמנים שנתתם ומציג את
מה שנאמר.

**הקפידו לפתוח כל תשובה בשאלה שקדמה לה.** זה מה ששומר על ציטוט שנתלש
מהקשרו הוגן, וזה גם מה שגורם לקטע לעבוד: צופה שרואה את השאלה מבין למה
התשובה חריגה.

## כתוביות סימטריות

השורות נשברות כך שהרוחב **המרונדר** של השורות יהיה קרוב ככל האפשר לשווה,
לא מספר התווים. בגופן פרופורציונלי ההבדל משמעותי — האותיות העבריות הרחבות
כפולות ברוחבן מהצרות — ובלוק שסימטרי לפי ספירת תווים עדיין נראה מרופט על
המסך. המדידה נעשית ב-Pillow על קובץ הגופן עצמו; בלי Pillow יש נפילה
לאומדן לפי תווים.

גודל הקטע נקבע לפי מה שבאמת נכנס בשתי שורות, לא לפי תקציב תווים: 60 תווים
נכנסים לשתי שורות של 30 רק אם גבול מילה נופל בערך באמצע, ואחרת הכתובית
גולשת לשורה שלישית ונחתכת בקצה הפריים.

הטקסט נכתב ל-ASS בסדר **לוגי**. ה-libass כאן מקומפל עם fribidi ומיישם את
אלגוריתם ה-bidi בעצמו, ולכן היפוך מוקדם של הטקסט (למשל עם `python-bidi`)
יגרום לעברית להירנדר הפוך. נבדק ברנדור פריים בשתי הדרכים.

## דגלים שימושיים ל-`build`

| דגל | ברירת מחדל | מה זה עושה |
|---|---|---|
| `--aspect` | `9:16` | גם `16:9`, `1:1`, `4:5` |
| `--fit` | `blur` | מילוי הפסים ברקע מטושטש; `crop` חותך למילוי |
| `--font` | בחירת fontconfig | משפחת גופן לכתוביות |
| `--text-width` | `0.84` | רוחב שורה מרבי כשבר מרוחב הפריים |
| `--max-lines` | `2` | שורות מרביות בכתובית |
| `--max-cue-secs` | `4.5` | משך מרבי של כתובית בודדת |
| `--margin-v` | `210` | שוליים תחתונים ב-1080p, מוקטנים לגובה הפלט |
| `--box` | כבוי | קופסה אטומה מאחורי כל שורה במקום קו מתאר |

## בדיקות

```bash
python3 test_edit_reel.py
```

הבדיקות מוודאות שכתובית לא חורגת ממספר השורות או מרוחב הפריים, שהשבירה
היא אכן הסימטרית ביותר האפשרית, שאף מילה לא נוספת/נופלת/מוחלפת בסדר
בדרך, ושחותמות הזמן נשארות בתוך הקטע שנחתך.

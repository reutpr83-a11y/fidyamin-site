# סרטון הסבר: עדכון התקציב, עיריית חריש

עריכת V2. Reel ציבורי מבוסס נתונים, בשפת העיצוב של הקמפיין הקיים.

## הקובץ המוכן

`out/harish-budget-reels-1080x1920.mp4`

| | |
|---|---|
| רזולוציה | 1080×1920 אמיתי, 9:16 |
| קצב פריימים | 30fps |
| וידאו | H.264 High Profile, level 4.2, yuv420p, faststart |
| Bitrate | 8.5 Mbps בפועל (יעד 14, תקרה 20) |
| אודיו | AAC 48kHz stereo, 192kbps |
| אורך | 48.2 שניות |
| Loudness | -14.0 LUFS integrated, True Peak -1.4 dBTP, LRA 4.6 |

הערה על ה־Bitrate: הבריף ביקש 12 עד 20 Mbps. הקידוד רץ עם יעד 14 ותקרה
20, ו־x264 סיים ב־8.5 כי בתוכן טיפוגרפי שטוח הוא מגיע לרוויה איכותית
לפני שהוא ממלא את היעד. התוצאה חסרת אובדן ויזואלי, וכפייה של 14 הייתה
מוסיפה בייטים של ריפוד בלבד. הכוונה של הדרישה, יצוא אמיתי ולא Proxy או
Upscale, מתקיימת במלואה. אם בכל זאת רוצים את המספר עצמו, מוסיפים
`-minrate 13M -x264-params nal-hrd=cbr` ב־`render.js`.

## סולם טיפוגרפי

משפחה אחת בלבד. Ploni לא קיים בסביבה, ולכן Heebo, בלי ערבוב.
בכל פריים לכל היותר שלושה גדלים ושני משקלים. הבדיקה אוטומטית.

| תפקיד | גודל | משקל | Line height |
|---|---|---|---|
| נתון מרכזי | 128 | 700 | 1.02 |
| נתוני מחלקות | 110 | 700 | 1.02 |
| כל מסר וכותרת | 84 | 700 | 1.08 |
| הסבר ופסקאות שמנת | 54 | 500 | 1.22 |
| תווית מחלקה בזהב | 42 | 700 | 1.20 |
| שמות חברי מועצה | 32 | 500 | |

נתוני המחלקות יצאו 110 ולא 120 כפי שהבריף הציע. הסיבה מדידה: המחרוזת
"1.325 מיליון ש״ח" ברוחב עמודה של 790px, שנגזר משוליים של 90px, לא
נכנסת מעל 110. בחרתי לשמור על השוליים.

כל שורה שבורה ביד כך שדבר לא מוקטן אוטומטית. זה מה ששומר על גודל זהה
לאורך כל הסרטון.

## הרצועה השמנת

הרצועה אינה יורדת עוד עד תחתית הפריים. הגובה שלה נגזר מהתוכן: 70px
ריווח מעל הטקסט, הטקסט, ואז הקצה האלכסוני. מתחתיה נייבי, ושם יושב
ממשק Reels. אין יותר שטח לבן ריק מתחת לטקסט.

## Sound Design

`sound.py` מייצר את הפסקול. אין בו שיר, אין מלודיה, אין תופי טריילר.

* 84 BPM
* פולס בס רך על כל פעימה, נכנס בהדרגה ולא מתחזק אחר כך
* Percussion יבש, טיק קטן אחד בתיבה
* שכבת Synth נקייה אחת שמחליפה אקורד בגבולות הפרקים
* שכבה נמוכה נוספת נכנסת ב־msg3, המעבר מהנתונים למשמעות
* במסך חברי המועצה כל השכבות יורדות מדרגה כדי שהטקסט יקבל את הקשב
* Resolve נקי של חצי שנייה תחת שורת הסיום, בלי Boom

בסך הכול חמישה אפקטים מובחנים: שלושה טיקים על שלושת המספרים, שכבה
עמוקה אחת במעבר, ו־Resolve אחד.

המיקס מוכן לקריינות: התדרים 250 עד 4000Hz פנויים יחסית. אם תיכנס
קריינות צריך להוריד את המוזיקה בכ־10dB ולהוסיף ducking עדין. עדיף
קול טבעי על קול AI.

## הרצה מחדש

### לינוקס ומק

```bash
node check.js          # שער QA. נכשל אם משהו חורג
node render.js sheet   # פריים אחד לכל מסך, ל out/sheet
node render.js frames  # רינדור וידאו ל out/video-only.mp4
python3 sound.py       # יצירת הפסקול ל out/score.wav
./master.sh            # מיסטור ומיזוג לקובץ הסופי
```

### ווינדוס, פאוורשל

התקנה חד פעמית:

```powershell
winget install Gyan.FFmpeg
winget install OpenJS.NodeJS
winget install Python.Python.3.12
npm install playwright
npx playwright install chromium
pip install numpy pillow
```

לסגור ולפתוח את הפאוורשל, ולוודא ש `ffmpeg -version` עונה. ואז:

```powershell
node check.js
node render.js sheet
node render.js frames
python sound.py
.\master.ps1
```

`render.js` מאתר את ffmpeg לבד: קודם משתנה הסביבה `FFMPEG`, אחר כך הבילד
של הקונטיינר, ואם אין אז מה שנמצא ב PATH. בווינדוס זה האחרון.

`check.js` בודק לפני כל יצוא: אין שורה שחורגת מהעמודה, אין יותר משלושה
גדלים ושני משקלים בפריים, אין טקסט מתחת ל־30px, אין תוכן מחוץ לאזור
הבטוח, והאורך בטווח 48 עד 55 שניות.

## מבנה

* `script.js` כל הקופי, סדר המסכים, משך כל מסך, ומשך הכניסה שלו
* `video.html` מערכת העיצוב ומנוע התזמון. `setTime(t)` דטרמיניסטי
* `render.js` צילום פריימים ב־Playwright ישירות אל ffmpeg
* `sound.py` הפסקול
* `master.sh` מיסטור ל־14 LUFS ומיזוג
* `check.js` שער QA
* `assets/` ארבעת הדיוקנאות, נחתכו מחדש לקנה מידה אחיד ולקו עיניים אחיד
* `fonts/` Heebo

## מה לא נעשה

* **קריינות.** אין הקלטה של קול אנושי. הבריף מעדיף קול טבעי על AI,
  ולכן המיקס הוכן עם מקום לקריינות שתתווסף בהמשך.
* **Ploni.** לא קיים בסביבה, ולכן Heebo לבד, כפי שהבריף מורה.

## כרטיס הסיום לקאט עם הדוברת

הקאט עם הדוברת נגמר על פריים קפוא של הפנים שלה, וזה נקרא כתקלת שידור
ולא כסיום. שלושה קבצים מחליפים את הזנב הזה בכרטיס סגירה:

| קובץ | תפקיד |
|---|---|
| `endcard.js` | הסצנה עצמה, באותה מערכת של `script.js` |
| `build-endcard.sh` | מייצר `endcard.html`, מריץ את שער ה־QA, ומרנדר ל־`out/endcard.mp4` |
| `append-endcard.sh` | חותך את הזנב הקפוא ומחבר את הכרטיס בדיזולב |
| `freeze-probe.py` | מאתר את הזנב הקפוא ומדווח מה מצא |

```
./build-endcard.sh
./append-endcard.sh out/harish-budget-presenter-1080x1920.mp4
```

`endcard.html` ו־`check-endcard.js` נוצרים מ־`video.html` ומ־`check.js`
ולכן הם ב־gitignore. **לערוך את המקור, לא את העותק**, אחרת הכרטיס יסטה
מהמנוע שמצייר את שאר הסרטון.

### על זיהוי הקפיאה

הסף של `freezedetect` תלוי במקור. בצילום מצלמה רעש החיישן מבדיל בבירור
בין פריים נע לפריים קפוא, אבל במושן גרפיקס שטוח הטיפוגרפיה עומדת במקום
בין הכניסות וכמעט כל פריים נראה קפוא. לכן `freeze-probe.py` מדפיס את כל
המועמדים ומציע חיתוך רק כשהעדות חד משמעית. כשהוא מסרב הוא מסביר למה,
והפתרון הוא להסתכל על הפריימים ולהעביר `CUT=` ביד:

```
CUT=41.8 ./append-endcard.sh out/harish-budget-presenter-1080x1920.mp4
```

**לא** להרפות את הסף עד שמשהו יוצא. סף רופף חותך באמצע משפט.

### פרמטרים

| משתנה | ברירת מחדל | מה הוא עושה |
|---|---|---|
| `CUT` | זיהוי אוטומטי | נקודת החיתוך בשניות |
| `TRANS` | `0.5` | אורך הדיזולב. `0` לחיתוך חד |
| `AFADE` | `1.6` | דעיכת הסאונד בסוף |
| `FREEZE_DB` | `-45` | סף הזיהוי |
| `OUT` | `out/presenter-with-endcard.mp4` | קובץ הפלט |

ה־`lead` של הסצנה ב־`endcard.js` עומד על 640ms כדי לבלוע את הדיזולב, כך
שהשורות נכנסות על שדה נייבי נקי. **אם משנים את `TRANS`, צריך לעדכן גם
אותו**, אחרת הכניסה מתרחשת מתחת למעבר ומתבזבזת.

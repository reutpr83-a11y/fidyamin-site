# מה להעלות כדי לרנדר מחדש את הריל הארוך באיכות מלאה

## הקובץ

**`06092026_155953.MOV`** בלבד. זה הטייק שהריל חתוך ממנו.

איך אני יודע: בניתי מסכת דיבור מהאודיו של הייצוא מוואטסאפ והצלבתי מול
מסכת המילים של כל אחד מארבעת התמלולים. `transcript_155953` קיבל 0.555,
`transcript_160335` קיבל 0.382, והשאר מתחת ל־0.09. התמלולים שמורים לפי

**לא צריך:** את `06092026_160335.MOV`, את `06092026_152356.MOV`, את
`youth-source.mp4` ואת הסגמנטים ב־`work/segs` וב־`workA/segs`. בדקתי את

## הבעיה: הקובץ גדול מהמותר

טייק של כ־157 שניות מהמצלמה שוקל בערך חצי ג'יגה, וגיטהאב חוסם קבצים
מעל 100 מגה.

### הדרך המומלצת: לפצל בלי לקודד מחדש

זה מפצל את הקובץ לחתיכות בלי לגעת בתמונה. אפס אובדן איכות.

```
ffmpeg -i 06092026_155953.MOV -c copy -map 0 -f segment \
       -segment_time 25 -reset_timestamps 1 155953_part%02d.MOV
```

יוצא כשבע חתיכות של כ־70 מגה. להעלות את כולן ל־`video/src/` בענף
`youth-source-upload`. אני מחבר אותן חזרה בלי קידוד מחדש ומאמת שהאורך
והסנכרון זהים למקור.

### אם זה מסובך מדי: ייצוא ב־1080x1920

```
ffmpeg -i 06092026_155953.MOV -vf scale=1080:1920 \
       -c:v libx264 -preset slow -crf 20 -c:a aac -b:a 192k \
       155953-1080.mp4
```

יוצא בערך 90 מגה, נכנס בקובץ אחד. זה עדיין **פי 1.875 ברזולוציה לינארית
ופי 20 בקצב הסיביות** לעומת מה שיש לי עכשיו, ולכן זו עדיין קפיצה גדולה.
פחות טוב מהפיצול, אבל הרבה יותר טוב מהמצב הנוכחי.

## מה יקרה אחרי שזה יעלה

הריל נבנה מחדש **בלי שום שינוי בעריכה**. אותם ביטים, אותם תזמונים, אותן
כתוביות, אותם פאנלים, אותו כרטיס סיום. משתנה רק:

| ב־`beats6.py` | מ | ל |
|---|---|---|
| `SRC` | `raw.mov` | הטייק המלא |
| `OFFSET` | 0.09 | נמדד מחדש, בשורת קוד אחת |
| `GRADE` | `hqdn3d` ואז הגדלה פי 2 | בלי הסרת רעש, והקטנה במקום הגדלה |

`hqdn3d` נמצא שם רק כדי להסתיר ארטיפקטים של הדחיסה, ו־`unsharp` רק כדי
להחזיר חדות שההגדלה איבדה. **שניהם יורדים.** מקור באיכות מלאה לא צריך
אף אחד מהם, וזה לבדו משפר את התמונה מעבר לרזולוציה.

זמן העבודה: כשעה, רובה רינדור.
